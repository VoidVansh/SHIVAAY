# Optional local semantic retrieval

SHIVAAY supports an optional SQLite-backed semantic index through `SemanticMemoryIndex`.
Unlike full-text search, embedding similarity can retrieve conceptually related memories even when the query uses different wording. This feature uses embeddings from local Ollama and does not require a cloud service or a Python vector database.

## Setup

Pull an embedding model in local Ollama, for example:

```bash
ollama pull nomic-embed-text
```

Then use the Python API:

```python
from shivaay_memory.engine import MemoryEngine
from shivaay_memory.semantic import OllamaEmbeddingBackend, SemanticMemoryIndex

engine = MemoryEngine()
index = SemanticMemoryIndex(engine, OllamaEmbeddingBackend(model="nomic-embed-text"))
index.index_all(project="SHIVAAY")  # indexes current active memories in this project

for memory in index.search("make it work without an internet connection", project="SHIVAAY"):
    print(memory["semantic_score"], memory["text"])
```

The first indexing pass computes one embedding per memory and may take time. Run `index_memory(memory_id)` after adding or correcting a memory; run `index_all()` to refresh the index. If you change embedding models, rebuild the index. Search only considers vectors generated by the currently selected model and matching dimensions.

## Privacy and limitations

- The adapter only accepts an HTTP loopback Ollama host and has no cloud fallback.
- Embeddings are derived data and remain in the same local SQLite database by default.
- Semantic search is optional and is not yet automatically wired into the interactive chat CLI. The default chat still uses lexical retrieval unless a caller explicitly adds this index.
- Similarity is a relevance signal, not proof that a memory is true. Review high-impact facts and corrections carefully.
